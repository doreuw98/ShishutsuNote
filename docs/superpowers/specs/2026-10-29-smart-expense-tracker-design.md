# スマート支出管理アプリ Web版 設計書

- 作成日: 2026-10-29
- 状態: Drew の承認待ち
- 対象: クラス発表用の新規プロジェクト
- 保存先: `expense-tracker-app/`（既存の Aturu アプリとは別のフォルダー）
- 参照仕様: `docs/reference/スマート支出管理アプリ_PRD_日本語.pdf`

## 意図と目的

日本の大学生が支出を記録し、月間予算と費目別の傾向を把握できるアプリを、スマートフォンとパソコンのブラウザーで動く Web アプリとして作る。アプリのインストールやアカウント作成を不要にし、授業で短時間に操作を見せられることを優先する。

## 目標

- 支出を日本語の画面からすばやく登録、編集、削除できる。
- 今日と今月の支出、月間予算の残額、残り日数から算出した1日あたりの目安を表示する。
- 履歴を検索・費目で絞り込み、費目別の月間支出と割合を確認できる。
- 画面幅375pxからデスクトップまで崩れず、発表時に主要機能を一連で実演できる。

## 対象外

初期版では、ログイン、サーバーやクラウド同期、銀行連携、レシート読み取り、複数人共有、複数通貨の換算、多言語切替を実装しない。これらは将来の候補として扱う。

## 検討した実装方法

1. **Expo / React Native** — ネイティブアプリらしい操作を実現できるが、授業で見せるには端末やシミュレーターの準備が増える。
2. **レスポンシブ Web（採用案）** — ブラウザーで直接開け、スマートフォンと教室のパソコンの両方で実演できる。画面は React + TypeScript + Vite、保存はブラウザーの localStorage を使う案とする。
3. **Python Streamlit** — 集計の試作は速いが、履歴操作やモバイルアプリ風の画面を細かく作る自由度は低くなる。

**選択案:** レスポンシブ Web。Drew が選んだ「授業で簡単にシミュレーションしたい」という目的に最も合う。React + TypeScript + Vite はこの案を具体化するための推奨であり、技術選択を最終承認する前の設計上の提案とする。

## 初期版の要件

- 画面表示は日本語、通貨は日本円（JPY）、金額は小数なし。
- 支出データはブラウザー内に保存し、再読み込み後も残す。サーバーへの送信はしない。
- 支出は金額、費目、日付、任意メモを持つ。金額は1円以上の整数とする。
- 今日・今月の支出合計は日本時間（Asia/Tokyo）で集計する。
- 月間予算は暦月ごとに設定する。月末までの日数は当日を含め、未使用予算は翌月に繰り越さない。
- 1日あたりの目安額は、`max（残予算, 0円）÷ 月末までの残日数` とし、円未満は切り捨てる。予算超過時は超過額を表示する。
- 予算の80%到達時にアプリ内で注意を示し、同じ月に重複表示しない。
- 費目別割合は今月の合計に対して算出する。月間支出が0円なら0%とする。
- 保存、入力エラー、削除確認、検索結果なし、記録なしの状態を画面上で明確に示す。

## 画面とレイアウト

- **ホーム:** 今月の予算の進み具合と1日あたりの目安を最初に確認できる。今日・今月の合計、最近の支出、追加操作を続けて配置する。
- **履歴:** 新しい順の一覧、メモ検索、費目フィルター、編集、確認付き削除。
- **分析:** 費目ごとの金額と構成比を横棒で示す。色だけに頼らず、費目名と金額も表示する。
- **設定:** 月間予算と初期費目を管理し、保存方法を案内する。
- **モバイル:** 1列レイアウトと下部ナビゲーション。主要操作は親指で押しやすい大きさにする。
- **広い画面:** 左にナビゲーション、右に読みやすい幅のコンテンツを置き、ホームの支出情報を整理する。

## ビジュアル方針

提供された PRD の濃紺とオレンジを識別しやすい色として引き継ぐ。背景は明るい青みのグレー（`#F2F5F9`）、本文は濃い墨色（`#202938`）、見出し・ナビゲーションは濃紺（`#17233B`）、主要操作はオレンジ（`#F26A3D`）、成功・予算内の状態は落ち着いた緑を使う。日本語のシステムサンセリフ体を使い、外部フォント取得に依存しない。装飾よりも金額、期間、予算との差が読み取れることを優先する。

この製品向けデザイン検索では、プロモーションページ向けの構成や日本語に合わないフォントが上位に出たため、その結果は採用しない。配色は PRD の図と内容に合わせ、一般的な可読性・アクセシビリティ指針を補助として使う。

## 制約と安全な扱い

- 初期版は1人が同じブラウザー内で使う想定。localStorage の内容は別端末に同期されない。
- ブラウザーデータを消すと記録も消える。初期版ではバックアップ機能を約束しない。
- 個人の支出データをアプリ外へ送らない。画面にはダミー記録を使い、実演で個人情報を入力しない。
- 外部サービス、認証、不要な依存パッケージを加えない。

## 受け入れ基準

- 有効な支出を追加でき、ホームと履歴に直ちに反映され、ブラウザーを再読み込みしても残る。
- 空欄、0円、負数、小数の金額を保存できず、金額欄の近くに修正方法が出る。
- 支出を編集・削除すると、日次・月次合計、費目集計、予算の残りが一致して更新される。
- 月間予算を設定し、残予算と1日あたりの目安を定義された式どおりに表示する。
- 履歴検索・費目フィルター、空の状態、削除確認が動作する。
- 画面幅375px、768px、1024px、1440pxで横スクロールが発生しない。
- キーボードで操作でき、フォーカスが見え、入力欄に常にラベルがある。色だけで意味を伝えない。

## 実装者に任せる範囲

小さなコンポーネント分割、React 状態管理、費目アイコン、余白やブレークポイントなどは、上記の目的と要件を保つ範囲で実装時に選ぶ。バックエンド、アカウント、将来機能は追加しない。
